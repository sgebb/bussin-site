Privacy and Security

Bussin is a client-side, zero-proxy web application. All message processing, credential caching, and layout operations happen directly inside your browser container. This document outlines exactly how your network connections and credentials are handled.

What Bussin Does

  • Direct Browser Connections: Renders UI and executes protocol exchanges locally. All AMQP messaging traffic flows exclusively between your browser process and Microsoft Azure's cloud gateways.
  • Delegated Token Caching: Uses the Microsoft Authentication Library (MSAL.js) to request standard OAuth 2.0 JWTs. Access tokens for Service Bus data-plane actions are stored solely in volatile session memory.
  • Local Configuration Caching: Saves your namespace bookmarks, workspace folder layouts, and dashboard settings inside your browser's sandboxed localStorage.
  • Auditable Analytics: Logs a lightweight profile record (User ID, email, name, and login timestamp) upon successful Entra ID authentication to our open-source, serverless tracker for adoption metrics. SRE teams can self-host this auditable tracker in their own Azure subscription using the provided C# source code and Bicep scripts.

What Bussin Never Does

  • No Proxy Relays: We do not operate any middle-tier servers, databases, or API relays that intercept or process your messages. There is no external infrastructure that can leak your message content.
  • No Payload Data Transit: Absolutely zero Service Bus entity names, queue definitions, metadata headers, or message body payloads are ever sent to, stored on, or processed by our systems.
  • No Telemetry Tracking: We do not include third-party advertising cookies, Google Analytics, or external session-replay recorders. All active connections run inside standard browser TLS envelopes.

OS Sandbox Boundaries

Because Bussin runs as a standard web application, it inherits the sandbox protections enforced by modern browser engines (WebKit, V8, Gecko):

  • Same-Origin Isolation: Cross-origin resource sharing rules prevent other websites or scripts from accessing Bussin's memory space or sandboxed local storage databases.
  • TLS Encryption: All direct communication with Microsoft management and data-plane endpoints is secured via standard browser-enforced TLS 1.2 or 1.3 channels.

Open Source and Auditability

Bussin is fully open source and transparent. SRE and security teams are encouraged to audit the codebase or self-host the static client and tracking functions:

  • Bussin App Core: Audit the client-side WebAssembly rendering, Rhea AMQP protocol logic, and local storage configurations: github.com/sgebb/bussin
  • Bussin Static Site: Audit this documentation site and static landing pages: github.com/sgebb/bussin-site
