Privacy and Security Policy

Bussin is a client-side web application. All message processing, credential validation, and UI operations happen directly inside your browser container. This document outlines exactly how your network connections and credentials are handled.

Data Flow and Connections

  • Direct Connections: All messaging traffic flows exclusively between your browser and Microsoft Azure's cloud gateways. We do not run middle-tier servers that process your messages.
  • Token Caching: Uses the Microsoft Authentication Library (MSAL.js) to request standard OAuth 2.0 tokens. Access tokens for Service Bus actions are stored only in temporary session memory.
  • Local Caching: Saves your namespace bookmarks, workspace folder layouts, and settings inside your browser's local localStorage.
  • Usage Metrics: Logs a basic profile record (User ID, email, name, and login timestamp) upon successful Entra ID authentication to our open-source, serverless tracker for adoption metrics. Teams can self-host this tracker in their own Azure subscription using the provided C# source code and Bicep scripts.

Data Protection

  • No Proxy Servers: We do not run backend servers, databases, or API relays that intercept or process your messages. There is no external infrastructure that can access your message content.
  • No Payload Data Transit: Zero Service Bus entity names, queue definitions, metadata headers, or message body payloads are ever sent to, stored on, or processed by our systems.
  • Google Analytics: We use Google Analytics to track general website traffic and help improve user experience. No Azure Service Bus connection details, secrets, or message payloads are ever sent to Google Analytics.

Browser Sandbox

Because Bussin runs as a standard web application, it inherits the sandbox protections enforced by modern browser engines:

  • Same-Origin Isolation: Cross-origin resource sharing (CORS) rules prevent other websites or scripts from accessing Bussin's memory space or local storage databases.
  • TLS Encryption: All communication with Microsoft management and data endpoints is secured via standard browser-enforced TLS 1.2 or 1.3 channels.

Open Source and Auditability

Bussin is open source. Security teams and developers are encouraged to audit the codebase or self-host the static client:

  • Bussin App Core: Audit the client-side WebAssembly rendering, AMQP protocol logic, and local storage configurations: github.com/sgebb/bussin
  • Bussin Static Site: Audit this documentation site and static landing pages: github.com/sgebb/bussin-site
