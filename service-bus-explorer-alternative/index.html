Azure Service Bus Explorer Alternative (Browser-based)

bussin is a browser app that connects directly to Azure Service Bus using AMQP over secure WebSockets. It surfaces namespaces, queues, topics, subscriptions, and dead-letter entities in the browser without a desktop client.

Problems with existing Service Bus tools

Many Service Bus tools require a desktop install, are limited to specific operating systems, and make live Service Bus inspection harder. That means slower onboarding, more setup steps, and extra friction when debugging production issues.

Desktop installation required

Desktop tools need downloads, local installs, and updates before they can be used.

OS limitations

Some tools are Windows-only or depend on Electron, which reduces access for macOS and Linux users.

Slow onboarding

Installing a client delays the first connection and adds friction for new users.

Lack of remote access

Desktop applications are bound to a single machine, which makes shared troubleshooting less practical.

Production debugging friction

When a live namespace needs inspection, local tooling can create wasted time and unnecessary complexity.

How bussin solves these issues

bussin turns the browser into the Service Bus client. It performs resource discovery, message inspection, and entity operations from the browser session, while preserving Azure RBAC controls and staying free of backend message relays.

Browser-side AMQP client

Connections are opened in the browser with a JavaScript AMQP client library over secure WebSockets.

Entra ID sign-in

Authentication uses browser-based Azure AD/OAuth flows, so the app works only with identities and permissions you already control.

Direct message workflows

Peek, send, receive/lock, complete, abandon, dead-letter, and resubmit messages directly in the browser using Service Bus protocol semantics.

FAQ

Do I need to install anything?
No. bussin runs in the browser and connects directly to Azure Service Bus using AMQP WebSockets.
Does bussin store my messages?
No. Messages are inspected in place through your Service Bus namespace and are not persisted by bussin.
Is this secure?
Yes. bussin uses Entra ID authentication and standard Azure Service Bus security for browser connections.
Does it work with production namespaces?
Yes. bussin is designed to inspect production Azure Service Bus namespaces safely and directly.
How does authentication work with Entra ID?
bussin uses Entra ID to authenticate users and authorize access to Service Bus namespaces via Azure identity.
