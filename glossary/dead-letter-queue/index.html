Dead-letter queue

A dead-letter queue holds Azure Service Bus messages that could not be processed normally. bussin.dev exposes dead-letter inspection and recovery directly in the browser.

Why messages go to the dead-letter queue

Messages are dead-lettered in Azure Service Bus when:

  • Max delivery count exceeded (message abandoned too many times)
  • Message expiration (TTL) exceeded
  • Filter mismatch on topic subscriptions
  • Explicit dead-letter operation (programmatic or manual)
  • Processing errors that trigger abandonment

The dead-letter queue preserves the original message body and metadata, plus system annotations like DeadLetterReason and DeadLetterErrorDescription, for investigation and recovery.

How to inspect dead-lettered messages

Dead-letter queues in Azure Service Bus are accessed via a special path: queueName/$DeadLetterQueue or topicName/subscriptions/subscriptionName/$DeadLetterQueue. You can:

  • View the dead-letter reason and exception details
  • Inspect the original message body and all properties
  • Check custom user properties and message annotations
  • Replay the message by re-sending it to the active queue
  • Archive or purge messages for cleanup

Why bussin helps

bussin.dev lets you open dead-letter queues directly in the browser using AMQP, eliminating the need for desktop tools or scripting. With bussin, you can browse, peek, and manage dead-lettered messages with full visibility into why they were dead-lettered, all while keeping your credentials secure in the browser.
