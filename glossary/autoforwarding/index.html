Autoforwarding (Azure Service Bus)

In Azure Service Bus pub/sub setups, it’s common to reprocess failed messages by sending them back through a topic.

In systems with multiple consumers, this can cause unintended side effects: a single retry can end up being processed by every subscriber that listens to that event.

What autoforwarding does

Autoforwarding is a feature where a subscription automatically forwards messages into a queue.

Instead of consumers reading directly from a shared subscription on a topic, each consumer reads from its own queue.

Model Shift: This changes the model from shared consumption to consumer-owned message handling.

Why this matters

When each consumer has its own queue, a few operational concerns become easier to manage:

  • Retries can be implemented per consumer
  • Monitoring and alerting can be scoped per consumer
  • Failures are isolated to a single consumer
  • Access control becomes clearer at the queue level
  • Reprocessing does not affect other consumers

The main shift is ownership: each consumer controls how it handles its messages.

The important part (DLQ and retry behaviour)

This becomes most obvious when handling failed messages.

If a message is sent back through the topic (for example after a DLQ retry), all subscriptions that match that event will receive it again.

In practice, that means:

  • Multiple consumers may process the same retry
  • You can introduce duplicate processing
  • You may trigger side effects in systems that were not involved in the original failure

If the message is instead sent back to a consumer-owned queue, only that consumer sees it again.

That keeps retries isolated and avoids affecting other consumers.

How to set it up

  1. Create a topic
  2. Create a subscription under the topic
  3. Create a queue for the consumer
  4. Enable autoforwarding on the subscription
  5. Point it to the consumer’s queue

From then on, the consumer reads from its own queue instead of the subscription.

When to use it

Use autoforwarding when:

  • Multiple consumers subscribe to the same topic
  • Each consumer needs independent failure handling
  • You want to avoid side effects when reprocessing messages

Summary

Autoforwarding turns a shared subscription model into a per-consumer queue model.

Each consumer owns how it processes, retries, and handles failures — without impacting other consumers.
