AMQP

AMQP stands for Advanced Message Queuing Protocol. It is the core wire protocol used by Azure Service Bus, and bussin.dev supports it directly over WebSockets from the browser.

Why AMQP matters for Service Bus

Azure Service Bus uses AMQP 1.0, the standardized Advanced Message Queuing Protocol, to transport message body, properties, annotations, and delivery semantics. It's a binary wire protocol that enables reliable, transactional message exchange—including features like message locking, settlement (complete/abandon/dead-letter), and session-based correlation.

Supporting AMQP 1.0 over WebSockets lets a browser client connect directly to Azure Service Bus without a backend proxy, accessing queues, topics, subscriptions, and dead-letter queues with full protocol fidelity.

Browser-native AMQP over WebSockets

bussin.dev uses the rhea JavaScript AMQP 1.0 client library to establish and manage AMQP sessions through a secure WebSocket channel (wss://). Once connected, your browser can:

  • Authenticate using AMQP CBS (Claims-Based Security) with OAuth JWT tokens
  • Send and receive messages with full AMQP message properties and annotations
  • Lock messages for transactional processing (peek-lock mode)
  • Settle message disposition (complete, abandon, or dead-letter)
  • Query entity metadata and dead-letter queues via the Service Bus management client

All of this happens directly in your browser—no backend intermediary, no credential exposure.
