Security and RBAC Configuration

Bussin is a static, zero-proxy client application. Because all API connections originate directly from your browser, access is governed entirely by standard Microsoft Entra ID (Azure Active Directory) App Registrations and Role-Based Access Control (RBAC) roles.

1. Entra ID App Registration Settings

To authorize Bussin, register a standard application within your Microsoft Entra ID tenant:

  • Application Type: Single Page Application (SPA). Web or Public Client platforms will fail during CORS or PKCE handshakes.
  • Redirect URIs:
    • https://app.bussin.dev (for active production console usage)
    • https://app.bussin.dev/demo (for testing with pre-mapped configurations)
  • Delegated API Permissions:
    • Azure Service Bus: user_impersonation (access URL: https://servicebus.azure.net/user_impersonation). This scope is required to open direct AMQP data streams.
    • Azure Resource Manager: user_impersonation (access URL: https://management.azure.com/user_impersonation). This scope allows Bussin to list subscriptions, namespaces, and entities.

2. Required Built-in Azure RBAC Roles

Ensure that your active user account or Entra ID security group is assigned appropriate RBAC roles on your Azure Service Bus Namespace or target entity level:

  • Azure Service Bus Data Owner: Full administrative privileges. Grants absolute data-plane access to send, peek, lock, complete, or dead-letter messages.
  • Azure Service Bus Data Receiver: Read-only data-plane access. Grants permissions to peek and receive messages.
  • Azure Service Bus Data Sender: Write-only data-plane access. Grants permissions to publish payloads to queues and topics.
Important: Traditional management roles (such as Owner, Contributor, or Reader) only apply to the Azure Resource Manager (ARM) plane. They do **not** grant data-plane access. You must explicitly assign one of the Azure Service Bus Data roles listed above to inspect and transit messages.

Local Storage Isolation

Favorite namespaces, folder groupings, and interface configurations are persisted inside your browser's sandboxed localStorage. This data remains under your exclusive control and is never synchronized to external servers.
