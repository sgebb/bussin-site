Security and Access Configuration

Bussin is a static web application with no backend server. Because all connections are made directly from your browser to Azure, access is managed entirely by standard Microsoft Entra ID (Azure Active Directory) registrations and Role-Based Access Control (RBAC) roles.

1. Entra ID App Registration

To authorize Bussin, register a standard application within your Microsoft Entra ID tenant:

  • Application Type: Single Page Application (SPA). Other types will fail due to security checks (CORS or PKCE).
  • Redirect URIs:
    • https://app.bussin.dev (for using the tool)
    • https://app.bussin.dev/demo (for testing the demo mode)
  • API Permissions:
    • Azure Service Bus: user_impersonation. This permission is required to open direct AMQP data streams.
    • Azure Resource Manager: user_impersonation. This allows Bussin to list your subscriptions, namespaces, and messaging entities.

2. Required Azure Service Bus Roles

Ensure that your Azure account is assigned the appropriate roles on your Azure Service Bus namespace or entity:

  • Azure Service Bus Data Owner: Full access to send, peek, lock, complete, or dead-letter messages.
  • Azure Service Bus Data Receiver: Read-only access to peek and receive messages.
  • Azure Service Bus Data Sender: Write-only access to publish messages.
Note: Standard management roles (such as Owner, Contributor, or Reader) only apply to the Azure management plane. They do not grant permission to read or write messages. You must assign one of the Azure Service Bus Data roles listed above.

Local Storage

Your folders, bookmarks, and settings are saved locally inside your browser's localStorage. This data stays under your control and is never uploaded to any external server.
