Workflow guide

Peek-lock inspection for Azure Service Bus

Peek-lock is the safest pattern for reading messages without committing them. Bussin.dev exposes this workflow with clear inspection controls and explicit completion steps.

Step 1: Open a queue or subscription

Select a queue or topic subscription from the namespace explorer. The UI shows active locks, delivery counts, and dead-letter availability.

Placeholder screenshot: queue state panel and message preview.

Step 2: Peek messages

Use the peek mode to inspect payloads, system properties, and metadata without removing the message from the broker.

1. Select peek mode
2. Review message body and properties
3. Confirm before completing or abandoning the message

Step 3: Complete, abandon, or dead-letter

After verifying the message, choose the action that matches your workflow. Bussin.dev keeps it explicit so you can audit every state change.

Why browser-native peek-lock works

Bussin.dev maintains an AMQP session over WebSockets so the browser can manage message locks and delivery state directly, without a backend proxy.
