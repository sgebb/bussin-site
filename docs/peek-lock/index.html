Workflow guide

Peek-lock inspection for Azure Service Bus

Peek-lock is the core pattern for safely reading messages without removing them from a queue or subscription. Bussin.dev surfaces this workflow with clear controls and explicit completion steps.

Step 1: Open a queue or subscription

Select the queue or topic subscription from the namespace explorer. The client shows live message counts, active locks, and whether the entity contains a dead-letter path.

This section should contain a screenshot of queue state and message list panels.

Step 2: Peek messages

Use the peek action to inspect payloads, headers, and delivery metadata without completing or abandoning the message. This preserves the message in the broker while letting you examine its contents.

1. Select peek mode
2. Review message body and properties
3. Confirm message is valid before completing

Step 3: Complete or abandon

After inspection, choose to complete, abandon, or move the message to the dead-letter queue. Bussin.dev keeps the workflow explicit so teams can audit message state changes.

Why this works in the browser

Bussin.dev uses AMQP over WebSockets so the browser can maintain a live Service Bus session and manage peek-lock leases without a backend proxy. That means the interface behaves like a native client while staying fully browser-native.
