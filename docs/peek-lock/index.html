Convenience Functions

Managing message locking, payload inspections, and dead-letter settlements inside the standard Azure Portal is often a slow, high-friction process. Bussin is built specifically to address these portal gaps, offering direct, fast, and convenient control over message life cycles.

Peek-Lock Message Actions

Bussin exposes standard AMQP 1.0 settlement states behind a clean, visual console interface:

  • Complete (Accepted): Confirms successful processing. Dispatches an Accepted settlement frame to immediately delete the message from the queue or subscription.
  • Abandon (Released): Rejects the current processing attempt. Dispatches a Released frame to immediately unlock the message so other active consumers can retry it.
  • Dead-Letter (Rejected): Moves malformed payloads to secondary DLQ storage. Dispatches a Rejected frame containing your custom diagnostic details.

Lease Expiry Countdown and Renewals

When you lock messages using Peek-Lock, the broker hides them from other consumers for a configured duration (default is 30 seconds). If your manual inspection takes longer than this window, the lock expires and the message is released back to active status, which can lead to duplicate processing.

Bussin actively tracks lock leases using the message's LockedUntilUtc property, displaying a live countdown in the preview panel. If you need more time, a single click triggers an on-the-fly lock renewal, extending the lease directly from your browser.

Safe Bulk Operations

Rather than writing complex PowerShell scripts to manage queue backlogs, Bussin provides built-in, non-blocking bulk operations. Move thousands of dead-lettered payloads back to the parent queue, or safely purge backlogs while keeping track of real-time progress meters.
