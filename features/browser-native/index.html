Feature overview

Browser-native Azure Service Bus access

bussin.dev is built as a browser-native client for Azure Service Bus. It uses AMQP over WebSockets to connect directly from the browser, offering live queue, topic, subscription, and dead-letter workflows without a backend proxy or desktop runtime.

Open App

What browser-native means

The application runs entirely in the browser and connects directly to Azure Service Bus using supported web transport. This eliminates install friction and keeps the tool lightweight for teams, while still supporting deep search, favorites, and message workflows.

Key capabilities

AMQP over WebSockets

Preserve Service Bus messaging semantics from the browser by connecting over secure WebSocket transport with no intermediary proxy.

Namespace discovery

Sign in with Entra ID and list your Service Bus namespaces, then browse queues, topics, and subscriptions without manual connection strings.

Message search and favorites

Filter by body, subject, properties, and dead-letter reason, and store favorite namespaces and folders locally in the browser.

Message workflows

Peek, receive/lock, complete, abandon, dead-letter, resubmit, or send messages from the browser with full message metadata visibility.

Where to use it

bussin.dev is ideal for developers, SREs, and integration teams who need to validate Service Bus state without installing a native client.
