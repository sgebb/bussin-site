What is bussin?

bussin is a browser-native Azure Service Bus explorer that runs as a Progressive Web App. It opens direct AMQP 1.0 sessions over secure WebSockets, discovers namespaces after Entra ID sign-in, and lets you inspect queues, topics, subscriptions, and dead-letter queues without a backend relay.

Problem it solves

Traditional Service Bus tools often need installs, desktop runtimes, or a proxy layer. bussin removes that friction by making the browser itself the Service Bus client.

Who it is for

Developer, SRE, and integration teams who need immediate access to live Service Bus entities and message workflows from any supported browser.

Why it exists

Because inspecting Service Bus should be fast, secure, and browser-native, with namespace discovery, message actions, and long-running operations all visible in the client UI.

Key features

Queue, topic, and subscription browsing

Inspect entity metadata, message counts, sessions, and dead-letter state with one browser-native explorer.

Deep search across messages

Search message bodies, IDs, subjects, properties, and dead-letter reasons; large scans can run in the background over up to 1M messages.

Saved favorites and preferences

Pin favorite namespaces, queues, and topics, organize them in folders, and store UI preferences in your browser using localStorage.

Background task visibility

Start background search or purge operations and keep them visible while you continue working in the app.

Live message workflows

Peek, send, receive/lock, complete, abandon, dead-letter, and resubmit messages directly from the browser UI.

Direct AMQP over WebSockets

Connect directly to Azure Service Bus with protocol-native AMQP over secure WebSocket transport, with no backend proxy.

Why browser-native matters

bussin runs as a static browser client and opens AMQP sessions directly to Azure Service Bus. That means no desktop client, no Electron wrapper, and no backend relay to manage.

  • No desktop client or Electron app.
  • No backend proxy required to reach Service Bus.
  • Works from any supported browser on Windows, macOS, or Linux.

FAQ

Does bussin store my messages?

No. bussin displays messages in the browser and does not persist them on a backend service.

Do I need a backend?

No. bussin uses AMQP over WebSockets directly from the browser to Azure Service Bus, so no backend proxy is required.

Is this secure?

Yes. bussin uses secure WebSockets and Azure Service Bus authentication and avoids extra server-side relays.

Does it work on Mac/Linux?

Yes. The browser-native design works across macOS, Linux, and Windows.

Does it support production Service Bus namespaces?

Yes. bussin is designed for real Azure Service Bus namespaces and production message inspection workflows.
