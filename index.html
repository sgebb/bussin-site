What is bussin?

bussin is a browser-native Azure Service Bus explorer that gives developers and operations teams fast access to queues, topics, subscriptions, and dead-letter queues. It connects directly over AMQP WebSockets and brings discovery, search, and browser-local conveniences to production debugging.

Problem it solves

Traditional tools require installs, platform-specific clients, or backend proxies. bussin removes that friction with a browser-first, protocol-native Service Bus experience.

Who it is for

Azure developers, cloud operators, and integration teams who need direct, low-latency access to Service Bus state and message workflows from any workstation.

Why it exists

Because inspecting Service Bus should be immediate and secure, with the same messaging semantics as native clients and the convenience of browser-local favorites, settings, and task tracking.

Key features

Queue, topic, and subscription browsing

See entity metadata, message counts, filters, and routing state in a consolidated browser UI.

Deep search across messages

Search message bodies, system properties, custom headers, and dead-letter reasons with quick filters.

Saved favorites and preferences

Pin favorite namespaces, queues, and topics, and keep your browser UI preferences locally persisted.

Background task visibility

Start a long-running bulk operation or cleanup task and keep working while it stays visible in the UI.

Convenience actions

Quickly resend, move to dead-letter, duplicate, or copy message metadata directly from the browser.

Direct AMQP over WebSockets

Connect using AMQP over secure WebSockets, preserving Service Bus semantics and avoiding backend relays.

Why browser-native matters

bussin runs as a static browser client and opens AMQP sessions directly to Azure Service Bus. That means no desktop client, no Electron wrapper, and no backend relay to manage.

  • No desktop client or Electron app.
  • No backend proxy required to reach Service Bus.
  • Works from any supported browser on Windows, macOS, or Linux.

FAQ

Does bussin store my messages?

No. bussin displays messages in the browser and does not persist them on a backend service.

Do I need a backend?

No. bussin uses AMQP over WebSockets directly from the browser to Azure Service Bus, so no backend proxy is required.

Is this secure?

Yes. bussin uses secure WebSockets and Azure Service Bus authentication and avoids extra server-side relays.

Does it work on Mac/Linux?

Yes. The browser-native design works across macOS, Linux, and Windows.

Does it support production Service Bus namespaces?

Yes. bussin is designed for real Azure Service Bus namespaces and production message inspection workflows.
