How it connects

No backend. No proxy. Just your browser and Azure.

bussin.dev serves static files and nothing else. Once the page loads, the connection is yours.

  1. 01

    Direct connections

    Your browser opens its own AMQP connection to *.servicebus.windows.net. Tokens and payloads never touch a Bussin server, because there isn't one.

  2. 02

    Your permissions, nothing more

    Every action runs under your own Data Receiver, Sender or Owner role. Bussin can't do anything your account couldn't do in the portal.

  3. 03

    Nothing stored on our side

    No logs, no telemetry on your messages. Security lists exactly what stays in browser storage and what lives only in memory.

What you can do

Everything you open Service Bus Explorer for, minus the install

The message-level work that fills a debugging session, in a tool that opens in a second on any machine.

Peek & search

Search message bodies, not just properties

Load thousands of messages without consuming them and filter on body content, broker properties or application properties. Search runs in browser memory, so delivery counts stay put and payloads never leave your machine.

Dead-letter recovery

Resubmit dead-lettered messages and remove the original

Read the DeadLetterReason, fix the payload inline, and send it back to its source in one step, for one message or a whole selection. The portal's resend leaves the original sitting in the DLQ.

Bulk operations

Purge and move in the background

Start a purge or a bulk move and keep working. Long jobs run as background tasks with progress, and session-enabled entities are drained session by session without asking you for a Session ID.

FAQ

Frequently asked questions

What is Bussin?

Bussin is an Azure Service Bus explorer that runs in a browser tab. It peeks and searches messages, settles peek-locks, edits and resubmits payloads, recovers dead-lettered messages, cancels scheduled messages, and manages subscription filters across queues, topics, and subscriptions. It connects straight to Azure over AMQP 1.0 on a secure WebSocket, so there is no backend and no proxy.

Is Bussin free?

Yes. Bussin is free to use and its source is available under BUSL-1.1. There is no paid tier, no account to create on bussin.dev, and no trial period. You sign in with your own Entra ID identity or paste a connection string.

Do I need to install anything?

No. Open app.bussin.dev and connect. There is no installer, no .NET runtime to add, and no administrator approval needed, which matters on locked-down corporate machines. If you prefer an app window and a dock icon, you can install Bussin as a Progressive Web App from the browser, or get it from the Microsoft Store.

Does Bussin work on macOS and Linux?

Yes, in any modern browser, including on ChromeOS, iOS, and Android. This is the usual reason people look for an alternative to the desktop Service Bus Explorer, which requires Windows 10 or later and .NET Framework 4.6.2 and otherwise needs Wine or a virtual machine. See the macOS and Linux guide.

Is Bussin a replacement for Service Bus Explorer?

For day-to-day message work, yes. For entity administration, no. Paolo Salvatori's Service Bus Explorer creates and deletes entities, edits queue and topic properties, manages authorization rules, and connects to the local emulator. Bussin does none of those. Many people keep both and reach for Bussin when they are on a machine where the desktop tool will not run. The comparison page goes through this feature by feature.

Do my messages or credentials pass through a Bussin server?

No, because there is no Bussin server to pass through. bussin.dev serves static files. Once the page has loaded, your browser opens its own AMQP connection to your namespace and the traffic carrying tokens and message payloads goes browser to Azure. Nothing is logged or stored on our side. Security sets out what is held in browser storage and what stays in memory only.

Can I use Bussin without an Entra ID account on the namespace?

Yes. Bussin accepts a standard Service Bus connection string in "Run without login" mode, which is how you reach a partner or customer namespace you have no directory access to. The Azure Portal cannot do this, since it only lists namespaces your signed-in identity can already see through Azure Resource Manager.

What Azure permissions does Bussin need?

Whatever your own identity already has. Azure Service Bus Data Receiver lets you peek and receive, Data Sender lets you send and resubmit, and Data Owner covers both. Every action runs under your existing RBAC assignments, so Bussin cannot do anything your account could not do in the portal.

Can Bussin connect to the local Service Bus emulator?

Not yet. The emulator currently accepts AMQP over TCP only, and a browser page can only reach an AMQP broker over WebSockets. We have asked Microsoft to add a WebSocket listener to the emulator, and a draft pull request for it is open, waiting on a public emulator image. Bussin will connect to the emulator once that ships. Until then, use a desktop client such as Service Bus Explorer for emulator work.
