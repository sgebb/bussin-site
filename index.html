What Bussin does — and what it does not do

Bussin only takes the actions you explicitly choose in the browser. The demo opens instantly without login or consent, while the full app requests Graph and Service Bus consent for discovery and direct Azure access. We do not store your Azure message or namespace data outside of basic analytics for this site.

Preferences such as favorites and light/dark mode are stored in your browser only. Bussin is open source — see the code at github.com/sgebb/bussin.

AMQP over WebSockets

Maintain a direct Service Bus connection from the browser using the same protocol layer that Azure expects for web clients.

Queue inspection

Browse queue metadata, active lock counts, and message state without removing items from the broker.

Dead-letter workflows

Open dead-letter queues, inspect failure details, and recover messages with explicit replay controls.

Topic subscriptions

Architecture overview

Bussin.dev is a static browser client that establishes AMQP sessions over WSS. The UI runs in the browser and interacts directly with Azure Service Bus endpoints, eliminating proxies and desktop middleware.

Frequently asked questions

Does Bussin.dev require a backend proxy?

No. Bussin.dev connects directly to Azure Service Bus using AMQP over WebSockets from the browser.

Can I use it on Linux and macOS?

Yes. Because it runs in the browser, Bussin.dev works across Mac, Linux, and Windows without platform-specific installers.

Is this a production-ready workflow?

Yes. The product is designed for developers and operators who need direct, secure access to Azure Service Bus workflows.
