Browser-based Azure Service Bus explorer

bussin.dev lets you explore Azure Service Bus resources directly from a browser. It uses AMQP over WebSockets for direct message access, with no desktop install or backend proxy required.

Open demo Open app

How it works under the hood

bussin.dev connects your browser directly to Azure Service Bus using AMQP 1.0 over a secure WebSocket channel (wss://). When you authenticate with your Azure credentials, the browser receives delegated OAuth tokens for both Azure Management (to list resources) and Azure Service Bus (to interact with queues, topics, and subscriptions).

The application uses rhea, a JavaScript AMQP 1.0 client library, to establish and manage the AMQP connection. Authentication happens at the protocol level using AMQP CBS (Claims-Based Security): your JWT token is wrapped in an AMQP message and sent to the $cbs endpoint for validation. Once authenticated, all message operations—send, receive, peek, and lock—happen directly in your browser with full AMQP protocol support.

No backend proxy or intermediary. Your credentials and messages never touch a bussin.dev server. All operations execute client-side, respecting your Azure RBAC permissions.

Message operations

  • Peek: Non-destructive read via the Service Bus management client
  • Send: Publish messages to queues or topics
  • Receive & Lock: Pull messages with transactional semantics (peek-lock mode)
  • Complete/Abandon/Dead-Letter: Settle message disposition
  • Dead-letter inspection: Access separate dead-letter queues for each entity

Browser-native benefits

  • No installer, no desktop runtime
  • Works in Chrome, Edge, Safari, and Firefox
  • Same experience across Mac, Linux, and Windows
  • Full AMQP protocol fidelity—same as native tools
  • Zero backend risk—credentials stay in your browser
