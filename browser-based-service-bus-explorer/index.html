Browser-native

Browser-based Azure Service Bus explorer

bussin.dev is a browser app that opens AMQP sessions directly to Azure Service Bus. It uses standard WebSockets and Azure identity tokens so the browser acts as the Service Bus client.

Open demo Open app

How it works under the hood

bussin.dev connects your browser directly to Azure Service Bus using AMQP 1.0 over secure WebSockets. When you sign in with Entra ID, the browser acquires delegated OAuth tokens for ARM namespace discovery and Service Bus messaging access.

The app uses a browser-side AMQP client and AMQP CBS token exchange so all Service Bus operations execute with protocol fidelity from the client.

No backend proxy or intermediary. The app serves static assets, while your credentials, tokens, and Service Bus traffic stay between your browser and Azure.

Browser-native message operations

  • Discover namespaces: List accessible Service Bus namespaces after Entra ID sign-in and consent.
  • Peek: Non-destructive broker reads to inspect messages without consuming them.
  • Send: Publish messages to queues or topics from the browser UI.
  • Receive & Lock: Reserve messages, then complete, abandon, or dead-letter them.
  • Dead-letter support: View dead-letter queues, resubmit messages, or move messages to DLQ.
  • Deep search: Scan payloads, IDs, subjects, and properties with filter-driven background searches for large message sets.

Browser-native benefits

  • Uses the browser network stack for secure WebSocket connections.
  • Keeps Service Bus identity and access tokens in the browser session.
  • Preserves AMQP delivery patterns like peek-lock and dead-letter routing.
  • Requires no server-side message relay or proxy.
