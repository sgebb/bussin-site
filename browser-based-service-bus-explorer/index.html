Browser-native

Browser-based Azure Service Bus explorer

bussin.dev lets you explore Azure Service Bus resources directly from the browser. It uses AMQP over secure WebSockets for direct queue, topic, and dead-letter access, with no desktop install or backend proxy required.

Open demo Open app

How it works under the hood

bussin.dev connects your browser directly to Azure Service Bus using AMQP 1.0 over a secure WebSocket channel (wss://). When you sign in with Entra ID, the browser receives delegated OAuth tokens for Azure Management and Service Bus, then discovers available namespaces and entities.

The application uses rhea, a JavaScript AMQP 1.0 client library, to establish and manage the AMQP connection. Authentication happens at the protocol level using Claims-Based Security (CBS): your JWT token is wrapped in an AMQP message and sent to the $cbs endpoint for validation. Once authenticated, all message operations—send, receive, peek, lock, complete, abandon, and dead-letter—happen directly in your browser with full AMQP semantics.

No backend proxy or intermediary. Your credentials and messages do not pass through bussin.dev servers. All browser-based interactions are controlled by your Azure RBAC permissions and explicit consent flows.

Browser-native message operations

  • Discover namespaces: Browse available Service Bus namespaces after Entra ID sign-in and consent.
  • Peek: Non-destructive read through the broker with peek-lock semantics.
  • Send: Publish messages to queues or topics from the browser UI.
  • Receive & Lock: Pull messages with transactional semantics, then choose complete, abandon, or dead-letter.
  • Search: Filter across message genres, payloads, properties, and dead-letter reasons.

Browser-native benefits

  • No installer, no desktop runtime.
  • Works in Chrome, Edge, Safari, and Firefox.
  • Same experience across macOS, Linux, and Windows.
  • Full AMQP protocol fidelity—same as native tools.
  • Zero backend risk—credentials and consent stay in your browser.
